# 维护者文档体系

[English](README.md) | [中文](README_zh.md)

## 概述

此目录存放 **Paradox Chronicle** 插件的全部维护者内部文档。

不同于项目根目录下的通用文档以及 `docs/` 目录下面向插件用户的参考文档站点，本目录下的文档面向**项目核心作者、长期维护者以及 AI 协同代理**。记录深入的系统设计规范、架构决策档案、疑难排查日志、性能基准剖析以及版本路线图。

### 语言与命名策略

- **正文语言**：主要以**中文**编写。这是为了保证单人核心维护时的思维密度、表达精准度并消除母语转换摩擦。
- **国际化与翻译**：非中文母语的读者或开发者若出于兴趣需查阅本文档库，推荐借助现代翻译引擎或 AI 助手（如 DeepL, ChatGPT 等）辅助阅读；未来如有外部英文贡献者补充维护者笔记，亦完全支持并欢迎直接提交英文版本。
- **文件系统与路径**：全量推行**小写 kebab-case 英文命名**（如 `snippet-match.md`, `roadmap.md`）。这彻底解决了跨平台文件系统兼容、Git 引用以及 URL 编码在 GitHub Web 端丢失锚点的问题。

### 1. design/ (系统设计规范)
插件顶层设计、UI 视觉体系与核心抽象模型的“活设计规范（Living Specifications）”，采取**人机共建**原则，由维护者确立原则，AI 协助整理与保持同步。

### 2. notes/ (人工核心心智区)
由项目核心维护者亲自编写、审阅与维护的权威知识库。其中架构决策（ADR）采用**自包含 RFC 风格**，一经实施即封存，永不过期。各子目录均提供同名的伴生索引文件（如 `adr.md` 索引 `adr/`），确保结构清晰易览。

### 3. ai-notes/ (AI 协同归档区)
低心理阻力的知识沉淀区与免责暂存区。文档**按原样归档（Archived as-is）**，**不承担与后续代码保持实时同步的维护责任**。成熟机制可按需晋升至 `design/` 或 `notes/adr/`。
